# A.2 用户账号、聊天隐私与可信写入边界

本文记录本地实现的安全机制与上线前限制，不表示已经部署，也不替代最终测试报告。本轮不接入热土引擎或真实 AI，不使用真实用户邮箱测试。正式人格名称、故事和内核仍由站长创作；账号与隐私流程不改写这些内容。

## 身份与凭据

普通用户使用独立的 User、UserSession、EmailVerification、PasswordReset 表。管理员继续使用原 AdminAccount/AdminSession，不复用普通用户 Cookie、角色或会话。管理员登录不等于用户登录；不存在默认允许管理员读取所有用户私人聊天的接口。管理员人格测试接口只接受归属该管理员的测试会话。

密码保持原 Argon2id 策略：memoryCost=19456 KiB、timeCost=2、parallelism=1；不保存明文密码。UserSession、验证和重置令牌只存 SHA-256 摘要；随机原始令牌仅用于 Cookie 或本地模拟邮件投递，不进入公共 API 响应、数据库或异常日志。验证与重置令牌分别有绝对有效期、authVersion、deliveredAt、usedAt、revokedAt。令牌先创建为未投递状态；模拟投递成功后才激活，未激活、过期、已消费或已撤销令牌均不可使用。重置密码与改密递增 authVersion，并撤销旧会话和其他可用凭证。

用户会话有 7 天绝对到期及 24 小时空闲到期。退出或单会话撤销后服务器立即拒绝对应旧令牌；绝对有效期不可原地延长。数据库异常不会降级为客户端布尔登录或跳过鉴权。用户 HTTP 响应使用字段白名单，不返回 passwordHash、会话摘要、令牌摘要或完整人格内核。

## Cookie、来源和 CSRF

生产普通用户 Cookie 为 `__Host-pv_v2_user`，采用 Secure、HttpOnly、SameSite=Strict、Path=/，没有 Domain 属性；预登录使用独立 Cookie 名称。明确隔离的本地 HTTP 环境使用不同 Cookie 名称且不设置 Secure。生产配置不满足 HTTPS/secure 条件时认证初始化失败。

所有修改请求保留可信 Origin 和跨站来源校验。匿名认证写入额外使用短期预登录 Cookie 与对应 CSRF 值；已认证写入使用绑定实际服务器会话的 CSRF 值。SameSite 不能替代这些检查。普通用户认证与管理员认证互不授予权限。

注册、登录、验证、重置、重发以及密码确认具有数据库持久化限制，包含账号/IP 时间窗，注册还有全局上限。IP 与邮箱限流标识采用数据库随机盐的 HMAC，不长期保存原始 IP。注销与改密复用密码确认限制，避免出现无限 Argon2 校验旁路。时间窗失效不等于自动物理清理：过期桶仍需受控清理任务。本轮未建立云端调度。

## 事务与撤销的顺序

认证与用户写入按 User → UserSession 的顺序锁定并重新读取状态。请求初次通过会话检查后，聊天创建、发消息、删除、资料修改等事务内再次调用 lockCurrent，检查账号状态、邮箱验证、authVersion、会话撤销与到期，防止旧页面在重置、注销或撤销后继续写入。

聊天所有者由服务端用户身份确定，客户端不能提交任意 userId。会话读写删除同时筛选 userId 和 deletedAt；消息按会话归属访问，不能通过修改 sessionId 跨用户获取内容。历史详情提供有上限的消息游标分页，历史列表与收藏也由服务端分页。

新建会话使用用户与 creationKey 的唯一关联。相同请求键返回原会话，不同人格意图拒绝；人格共享锁取得后再次核对发布状态、版本和 slug。消息以持久化客户端幂等键去重，重复键的不同正文拒绝。消息发送在会话锁及人格状态复核后写入，不因旧前端页面仍显示“可发送”而忽略下架或关闭状态。

费用相关删除先锁 AiControl，再按用户与会话顺序执行，和费用执行器的主要锁序保持一致。数据库可能因其他复杂交错拒绝或回滚事务；调用方不能将失败当作完成，也不能在数据库失效时绕过费用检查。

## 旧匿名会话与历史

0007 在原会话上增加独立 userId，但不回填、不自动认领旧匿名记录。管理员、访客、普通用户三个所有者必须恰有一个，创建后不可换绑；人格、固定内核版本及创建幂等键也不可更改。

正常运行模式要求已验证的用户登录后才能新建或继续普通用户聊天。旧匿名记录只允许凭原有效匿名凭据读取/清理，不能转给未经验证的账号。原匿名自动化回归通过显式、仅限 test 的隔离模式保留，不是实际网站的匿名聊天开关。该模式不得作为生产默认。

人格下架或归档后，用户自己已有历史仍可读取；会话名称与标识取其固定版本的档案快照，不借此泄露站长当前未发布草稿或内核。新消息仍按实时状态规则拒绝。

## 删除、注销与不可变账本

聊天删除在同一事务中先关闭会话并写入不可逆的 deletedAt，再启用窄范围隐私擦除意图，清空 ChatRequest.inputText/response，物理删除 ChatMessage。0007 只允许该单向正文擦除；它不能修改请求所有者、人格版本、状态、指纹、计价或费用记录，也不能恢复已删除的正文。删除后相关用户 API 不再返回会话，不能继续发送。

费用使用记录、价格版本、预留及追加账本继续保持原不可变约束。费用执行器若在删除后完成已开始的执行，仍记录应有的会计结果，但不恢复消息或响应正文。删除不表示供应商费用不存在，也不允许用隐私操作抹掉待对账敞口。

保留的 opaque 用户/会话 ID、请求指纹、版本关系与费用记录属于**假名化审计元数据**，不是完全匿名数据。需要后续确定保留期限、访问角色、备份生命周期及最终销毁流程；不能声称正文删除同时擦除了所有备份或所有可关联信息。

注销需要有效用户会话、CSRF 和受限流的当前密码确认。事务擦除其未删除聊天与收藏、撤销会话/验证/重置凭证，清空资料并替换邮箱、禁用密码和账号状态；保留必要的不变关联，不能重新激活已注销账号。相同邮箱后来重新注册是独立身份，不能获取旧账号历史。

当前注销按全部历史会话在一个有超时的事务内处理。极大账号可能超过 20 秒并整笔回滚，必须明确返回失败，不能假称注销完成。生产前需要评估即时封禁/撤销加受控分批擦除、容量治理和恢复机制。

## 本地模拟邮件

本轮没有 SMTP、收费邮件 SDK 或真实邮件发送。Node 本地适配器写入受限目录中的 0600 私有文件；Workers 通过仅回环、随机端口、随机 capability 的本地桥投递到同类私有 outbox。桥只有投递接口，没有公开读信接口，不在日志打印凭据；网页不能读取 outbox。手工本地演示和测试完成后需要清理这些文件。

邮件链接的令牌使用 URL fragment，页面读取后清除，避免把原始令牌放到服务端 GET 查询日志中。生产邮件流程本轮统一返回未配置错误，不能假装成功。缺少本地适配器也明确拒绝。

已配置的本地模拟请求统一以“已受理、不确认送达”响应，不能从公开响应判断邮箱是否存在或某次是否实际投递。模拟投递失败时令牌保持未激活/撤销，不能被验证或用于重置；数据库失败仍按错误返回。本实现降低账号枚举风险，不宣称网络时序严格不可区分。生产邮件需要可靠投递/队列、重试和告警设计。

## 数据库权限与生产依赖

SQL 约束验证数据关系与状态，不能识别 HTTP 管理员身份。`personaverse.privacy_action` 只是可信服务事务的操作意图，并不是数据库自行确认用户授权；API 的所有者验证不可省略。应用数据库账户应采用最小权限，与能执行迁移/DDL 的账户分离；数据库超级用户仍能绕过任何应用保护。本地隔离迁移/故障测试账户不是生产最小权限验收。

仍需独立验证生产 HTTPS 与真实 Safari、可信边缘 IP、防伪转发、托管 PostgreSQL/Hyperdrive 的敏感查询无缓存、正式邮件投递、备份恢复、隐私保留与清理调度、线上资源限额。当前用户 AI 路径仍默认关闭；本轮不启用外部身份提供方或真实模型。
