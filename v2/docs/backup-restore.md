# 备份与恢复规划（尚未执行）

Git 分支只备份代码。PostgreSQL 数据、上传头像、密钥配置须分别保护。本阶段不访问旧版 SQLite 或任何生产数据库。

正式部署前明确数据库所有者、迁移账户和应用最小权限账户；使用专用 V2 数据库，不在旧库直接运行此迁移。

建议：每日加密逻辑备份 + 按业务恢复目标配置 WAL/PITR；保留 7 日/4 周/月度副本；异地保存并限制访问。实际周期和 RPO/RTO 由站长批准后确定。密钥不得与备份明文放一起。

恢复先在隔离数据库验证：备份校验和、迁移台账、行数/外键、管理员会话撤销、内核版本不可变和聊天归属；记录恢复时长。上传文件与数据库版本匹配。生产切换需另行审核，不由本阶段启动脚本执行。

失败迁移优先采用审查过的向前修复；不自动删除表、回滚作者内容或改写既有迁移。后续每次迁移都要检查手写 SQL 触发器和 CHECK 是否保留。
