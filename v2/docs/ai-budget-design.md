# Phase 4A：模拟 AI 费用安全底座

本轮只执行确定性 Fake Provider。金额、价格、token 与对账证据全部为模拟数据。无真实供应商实现、无 API Key 配置入口、无外部 AI HTTP 调用；不代表真实计费已经验收。

## 已实现的可信写入边界

`apps/api/src/ai/engine.ts` 是唯一业务写入入口。PostgreSQL 的应用账户应禁止 DDL、禁用触发器、修改迁移和绕过应用服务；迁移账户独立保管。当前本地容器账户用于隔离迁移/破坏性约束测试，不是已验收的线上最小权限账户。数据库超级用户仍可破坏任何应用约束，不能宣称 SQL 能识别管理员 HTTP 身份。

公开模拟费用入口 `/api/v1/chat/sessions/:id/ai-requests` 与管理员 `/api/v1/admin/test/sessions/:id/ai-requests` 分离；管理员入口保留数据库会话、角色、Origin、CSRF。访客只接受当前环境的 Cookie 名称，服务端复核会话归属及有效期。服务默认禁止费用实验，只有 `environment=test` 与服务构造参数 `fakeBudgetTestMode=true` 才能打开实验入口；还需数据库显式启用、正数限额、价格及全部预算。正常开发和生产均不能借此调用真实模型。

## 预算与精度

最小单位为 `10^-8` 币种单位，JavaScript BigInt / PostgreSQL BIGINT，范围 `0..999999999999999999`，与既有 `Decimal(18,8)` 匹配；不使用浮点金额。价格是不可变版本，每输入/输出 token 的整数单位价格，币种使用大写三字母代码。本阶段数据库拒绝非模拟价格。

一次预留必须同时满足：全站 UTC 日、全站 UTC 月、访客 UTC 日和累计预算；管理员改用独立 UTC 日测试预算，仍消耗全站日/月预算，不套访客额度。预算缺失、零预算、开关关闭或余额不足全部拒绝。

预留上限 = 保守输入量 × 输入单价 + 最大输出 token × 输出单价。输入采用完整固定内核、开场白、历史与新消息的 UTF-8 字节数，加固定 128 与每消息 32 的封装余量；不截断、不改写作者文本。本轮只是 Fake 协议的保守模拟，真实 DeepSeek 必须验证实际序列化、tokenizer 和计费规格后才能启用。

`reserve()` 在单个交互事务中锁 `AiControl(global) FOR UPDATE`、会话及相关预算行，完成状态/权限/限流/预算检查、创建请求、增加所有预留余额、创建 hold 和追加 reserve 账本。多实例必须共用同一 PostgreSQL；禁止在事务外先查余额后扣款。全局锁牺牲吞吐量换取可审查的正确性，未来分片需重新证明锁序与原子性。事务内没有供应商等待。

跨 UTC 边界的请求仍结算到原预留周期；新周期须显式配置新预算，不自动复制余额。币种分别建账，不相加。修改价格后，尚未派发的旧价预留被释放；已派发按原价格版本处理。

## 数据库关联和账本

新增 `0005_ai_safety` 与 `0006_ai_ledger_precision`，0001—0004 保持原样。

- `ChatRequest(sessionId, coreVersionId)` 复合外键绑定 `ChatSession(id, coreVersionId)`；会话归属继续由 0004 不可变触发器保护。
- `AiUsageRecord(sessionId, requestId)` 复合外键绑定 `ChatRequest(sessionId,id)`，不能跨会话挂账。
- 每请求唯一 reservation、唯一 reserve 账目和唯一 settle/release 终结账目；证据摘要全局唯一，拒绝重复结算。
- 价格、账本、使用记录、安全事件、hold 关联不可普通 UPDATE/DELETE；预留只允许 held→settled/released。请求身份和输入不可改，终态不可改。
- 对账调整通过新 `adjust` 账目追加，有符号整数、证据幂等，既有确认账目不覆盖。正向追加意外费用同时熔断；负调整不能使账户累计花费变负。
- 币种关联、非负数、精度、合法状态、每会话至多一个 reserved/running/unknown 均有 SQL 约束。
- 0005 遇到旧 ChatRequest/AiUsageRecord 行立即事务失败，要求站长审核迁移方案；不静默回填原始内容、费用或历史。新库可以完整重放。

余额的业务汇总与授权依赖可信服务事务，不宣称数据库触发器自动验证所有会计业务或 HTTP 管理员身份。

## 幂等与状态机

服务端 UUID 请求 ID；会话内客户端 UUID 幂等键；SHA-256 指纹包含会话、键、完整输入与输出上限。相同内容返回当前状态/已保存结果，不重复派发；同键不同内容冲突。普通 mock 消息接口不能在费用请求活跃时插入消息。

```text
pending → reserved → running → succeeded
    ↘ failed     ↘ failed  ↘ failed（仅明确未计费）
                              ↘ unknown → succeeded / failed（凭证对账）
```

reserved 带 30 秒租约；派发获取全局锁、会话锁和人格共享锁，重新检查关闭、下架/归档、预算削减、输出/输入上限、价格、总并发及开关。失败在同一事务释放预留并终结；成功转 running、fencing token 增加、5 秒执行租约。只有获得本次 `granted=true` 的执行者可调用 Fake Provider，重复执行者不能重用 running 状态派发。结果写入必须匹配 token 与 running 状态。

“派发授权提交”是本轮模拟器的线性化边界。人格下架/关闭在它之前完成则阻止派发并释放；其后发生视为已开始执行，不能抹去费用。外部 HTTP 与数据库无法原子提交：未来应记录发送/接收证据，授权提交到供应商接收的窗口按可能已派发处理，不能承诺下架可撤销供应商费用或外部 exactly-once。

## 故障、恢复与熔断

确定未接收且不计费的 Fake 错误才允许 release。超时、可能收费错误、派发后数据库记录失败都保留预留，转 unknown；unknown 占用并发与会话槽位，禁止自动重新调用。连续三次明确失败或任一未知结果打开全局熔断。数据库失联不能绕过预算。

`recover()` 使用同一全局事务锁及递增 token，跨实例串行恢复：过期 reserved 释放；过期 running 转 unknown、保留预留并熔断。不存在把 unknown 自动当作免费失败的路径。旧执行者回写被拒绝。恢复函数不联网；测试命令 `pnpm ai:recover:test` 仅允许隔离本地 PostgreSQL。未建立云端定时任务，未来部署前必须授权并配置恢复调度及告警。

`reconcile()` 只接受受控服务调用和 SHA-256 证据标识，幂等终结 unknown；不提供公开对账接口。测试里的模拟证据不等于真实账单证据，也不验证供应商签名。真实接入需独立审核、权限与审计；供应商不支持幂等/逐请求账单时，无法保证严格外部 exactly-once。

## 持久化资源限制与隐私

数据库时间窗涵盖 IP、身份分钟/每日次数；新建会话有独立技术速率与访客活动会话上限；请求有长度、上下文、输出、每会话并发及全站 running/unknown 上限。管理员测试有独立预算和技术保护，未套用访客日预算。

IP 用数据库随机盐 HMAC，不写原始 IP；分钟/日计数保留约 24/48 小时，恢复时删除过期桶。盐仍须按受限数据保护。匿名身份可更换，不是可靠的真人级防刷。当前 `trustProxy=false`：不信任任意转发头。Cloudflare 真实入口的客户端 IP 只能在可信边缘读取并通过私有 Service Binding 传递，需后续防伪与集成测试；现在不能声称已具备真实边缘 IP 限流。

异常事件仅保存请求 ID、错误类别和时间，不写完整内核、对话或密码。ChatRequest/消息作为业务存储保存原文，不是异常日志；其隐私保留策略与审计账本分离仍需下一阶段明确。
