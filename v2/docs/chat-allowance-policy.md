# 每日60分钟聊天额度：本地Mock验收

日期2026-11-17；基线1677672dfe34e0e708d14899b9ccaa0a8a67f7c1；分支feat/v2-minimal-mobile-ui。仅v2内修改、仅本地提交，不推送或部署。DeepSeek真实调用继续关闭，所有回复和Token用量均为Mock。

## 产品规则

- 普通账户必须注册、验证邮箱并通过服务端会话认证；每日北京时间00:00获得3600000毫秒，即60分钟。没有“每天10条AI回复”的个人业务限制。原有消息长度、会话历史容量、分钟速率等技术保护保留。
- 普通用户同时受每日100000 Token保护额度限制。这是本轮选择的保守Mock默认值，不是站长已确认的正式商业套餐；本轮尚无后台额度配置编辑器。Token按UTF-8上下文、人格原文/开场白、历史、请求、固定模拟回复及消息框架估算上界，明确不是DeepSeek实际usage或真实账单。额度不足拒绝新消息，不截断、重写人格原文。
- 独立管理员后台/测试聊天不调用普通用户计时和个人Token配额。新费用预留只持有全站日/月预算；不再要求按管理员ID设置admin-test个人预算，也不套个人每日请求数。全站熔断、单次费用、上下文/输出安全上限、分钟限流、并发、超时仍有效。
- 历史admin-test预算及费用记录不回填、不删除、不篡改。财务账本原有UTC日/月周期保持，普通账户免费时长与个人Token按北京时间日桶切换，两者不是同一额度。
- 同一浏览器同时有用户和管理员Cookie时，普通用户接口仍按用户身份计量；不能用管理员Cookie自动冒充用户。管理员豁免通过独立管理接口实现。
- 游客可以浏览资料及`/demo`固定演示。该页不创建会话、不接受自由输入、不调用模型。数据库模式下访客不能新建聊天或调用真实AI。旧匿名mock-regression模式只用于原回归测试，不是新的线上免费方案。

## 活动计时的准确边界

采用服务端短租约，而不是浏览器累加器：页面每10秒尝试确认，租约最多30秒；消息发送、输入/点击/滚动活动由服务端收到后打时间戳。心跳只确认在线，不刷新最后活动时间，连续300秒没有活动则停止计时。前端不上传时间戳、时长、剩余额度或Token数，未知字段被拒绝。

服务端每次结算只计算`[settledAt, min(serverNow, leaseUntil, activityAt+5分钟, 会话撤销/过期时间)]`；仅对未结算的区间增加日累计。GET额度会结算已获准的有限区间，但不能续租。页面隐藏、退出页面、组件卸载时尽力暂停，隐藏/离线时不再发送定时心跳。即使关闭页面、断网导致暂停请求未送达，**最多再计最后30秒未确认租约**，不会无限扣时。这是有限容错窗口，不承诺关闭瞬间零额外秒数。

初次打开页面不自动开始计时；发消息，或随后用户输入活动触发开始。分钟额度耗尽、Token不足或跨日不依赖浏览器时区，服务端采用UTC+08:00日期，跨午夜的有效区间拆分到两个日桶。未用时间不结转；新日无需cron，首次请求自动得到新日桶。

前端显示服务端已确认的剩余分秒、Token保护余额、计时/暂停/其他设备状态和北京时间重置说明，最多约10秒一次更新，不把客户端倒计时当账本。额度拒绝会保留草稿、解除待重试输入锁并重新读取额度；后续有效请求可恢复。正式精确usage和真实模型接入不在本轮完成范围。

## 多设备、幂等和事务

新增迁移`0009_chat_time_allowance`，不改0001—0008：

- `UserChatDay`：复合主键(userId, 北京日期)，usedMs与usedTokens。SQL CHECK限制0—3600000和0—100000，防负数与越界。
- `UserChatClock`：每用户唯一时钟，绑定认证UserSession、ChatSession和服务端随机leaseId。复合外键阻止指向其他用户的登录会话或聊天；CHECK保证租约字段完整和时间边界一致。
- `ChatActivityEvent`：每用户唯一eventId、请求指纹、响应快照和时间。指纹含认证会话、聊天、动作及租约；相同ID不同内容409，相同操作返回原结果，不再次扣减或延长租约。只记录额度元数据，不记录密码、聊天正文或人格内核。

所有计数和时钟变更在持有User行锁的数据库事务中完成；消息去重先于消费，消息保存与Token扣减同事务提交。普通Mock发送按统一顺序锁全局AiControl、User、ChatSession/人格，检查全站熔断、归属及发布状态，再计量。失败整笔回滚。管理员Mock也遵守全站熔断；费用实验仍经过原全站原子预算引擎。

同一用户只有一个活动时钟，多设备/多标签不能叠加额外时间。另一设备的普通心跳/start不能续用当前设备租约；经认证的新消息可以原子接管，产生新租约并使旧设备心跳失效。跨设备余额与历史来自同一数据库。用户可以选择暂停，匿名身份不被当成可靠的真人身份。

客户端可以伪造自己的“活动”声明，因此不能证明真人真的在阅读；这只会消耗自己的时长，不增加额度。Token预算独立限制回复资源；服务端不接收客户端扣减数。不得把短租约描述成完整机器人识别方案。

## 费用与真实AI边界

当前个人`/messages`只有固定模拟回复，真实费用为零；计量数据明确为Mock。个人`/ai-requests`继续503 AI_DISABLED，游客不能调用真实模型。全局circuitOpen会同时拒绝新的普通及管理员Mock消息；重放已完成消息不会再次消费。

本轮没有把真实DeepSeek接到新时钟。未来收费派发必须将用户时间/Token预留与全站货币预算结合，在派发边界再次验证身份、租约、人格/会话和预算，保留unknown结果及对账机制；不能只用今日Token计数冒充真实供应商usage或已完成费用结算。预算默认零、模型默认关闭的保护保持。

## 数据与环境

只有本地、带归属标签的隔离PostgreSQL16。环境重启后原测试容器停止、端口变化，旧连接测试失败/跳过；恢复同一测试容器并更新私有本地端口后重新执行。tmpfs重建后旧预览元数据私下归档，不复用不存在的schema；新预览重新执行0001—0009，随机Owner/Viewer和test.invalid用户均为隔离测试数据。没有删除真实用户记录或连接生产库。

软注销用户后，旧会话撤销、聊天正文清除；新表只保留用量和幂等元数据，未把私人内容写入账本。新表外键阻止随意物理删除被引用的财务身份。日桶与事件的长期保留/清理策略、正式数据库最小权限及备份恢复仍需在上线前审核；本轮没有实现自动清理或管理员额度编辑器。
