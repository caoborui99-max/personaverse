# 工程安全与 Soul Core 最小架构

## 分支、范围与变更

基于已验收整合提交 `8e50f81ccdfbbd6a2e3863942662de765d0912a3`，独立分支 `phase2/soul-core-foundation`。不修改 main 或现有静态发布分支/产物，不部署、不触碰生产数据库、不使用任何真实 AI Key。本轮所有数据库写入仅发生在隔离测试夹具。

- `server/migrations.js`：从编号SQL文件运行独立迁移，逐版本事务提交DDL/回填/执行记录，保存SHA256、编号及执行时间。已执行版本跳过，内容或未知版本不匹配时拒绝；旧索引缺少公开状态列的兼容路径保留。旧库没有台账时通过幂等SQL接管，不重置旧资料。
- `scripts/dev-server.js`：启动仅检查就绪，不迁移、不导入种子。现有数据库缺少迁移/初始化/关联则拒绝启动，SQLite不存在时不创建文件。
- `server/database.js`：统一迁移模块出口，加入必须存在选项；移除重复表结构。`server/ai-chat.js`仅移除重复AI表定义，Provider与聊天行为未新增真实调用。
- `server/handler.js`：API只读校验就绪，管理员Core路由，创建人格与关联同事务，拒绝客户端选择其他核心。显式初始化可修复回滚后缺失关联，不改角色JSON。仅独立迁移脚本调用初始化，启动/构建/API不调用。
- `server/soul-core.js`：空草稿、手动编辑、不可变发布快照、活动版本切换、回滚、修订号冲突保护、事务审计事件与历史分页。无AI生成入口。
- `admin.html` / `js/soul-admin.js`：复用现有后台，增加手机可操作的核心面板、载入/保存、发布/回滚确认、历史分页；登出时清空核心文本。不进入静态预览。
- `tests/soul-core.test.js`：8组新增测试。`tests/integration.test.js`增加启动不迁移测试。浏览器与代理夹具改为先显式迁移各自临时数据库；浏览器脚本增加核心编辑/发布/回滚场景（本轮环境阻塞，未声称通过）。
- README与大陆部署说明：先迁移后启动，不加入systemd的ExecStart/ExecStartPre。

## 数据结构

新增表：

1. `schema_migrations`：迁移ID、checksum、applied_at；目前记录0001至0004四个版本。
2. `soul_core`：固定唯一id=`shared`，draft_content默认空字符串、revision、active_version_id（初始NULL）、last_operation、updated_at。
3. `soul_core_versions`：不可通过API修改的发布快照；id、固定core_id、修订号、管理员手动内容、创建者与时间。
4. `persona_core_links`：persona_id主键/外键，core_id被约束为shared。关联保存在独立表，不改旧人格JSON或ID；包括已有下架/软删除角色。
5. `soul_core_events`：草稿保存/发布/回滚的操作者与修订记录，不复制内容到日志。

新迁移文件 `db/migrations/0004_soul_core.sql`：创建唯一空核心并关联已有角色。没有默认核心文案、自动生成、自动发布或新AI调用。历史版本起初为0条。

第十三个人格通过现有后台/API创建时，后端在同一事务写入角色和共享核心关联，无需修改前端人格数组。任意数量的新角色使用同一机制；容量与并发仍受单机资源限制。共享核心不修改角色独立背景、性格和提示词。

本轮只建立共享版本入口：人格关联逻辑核心，核心指向生效版本；尚未把Core加入AI请求，也未新增独立长期记忆/会话版本锁定。此为下一阶段范围，不能声称AI已经共享核心。

## API与权限

- GET `/api/admin/soul-core`：返回管理员草稿与最近20个发布版本，可用before修订号继续分页。
- POST `/api/admin/soul-core/draft`：`{revision,content}`，手动保存；最多20000字符，允许空草稿。
- POST `/api/admin/soul-core/publish`：`{revision}`，发布已保存非空草稿；创建快照并切换活动引用。
- POST `/api/admin/soul-core/rollback`：`{revision,versionId}`，切换到历史发布版本；不改变当前草稿、不删除历史。

全部要求服务端管理员会话；写操作保留同源JSON检查，拒绝未知字段。过时修订返回409；不存在版本404；空白发布400。发布、指针与审计采用事务和乐观并发，只有一次请求获胜。数据库单例/外键约束防止第二核心和悬空关联。

没有普通用户读取原文的接口；公开人格字段白名单与静态产物不包含Core。管理员本身仍能读取内容，这是管理所需权限。数据库运维账户可直接改数据，不属于应用权限边界；已发布版本在API层不可编辑，数据库凭据仍应严加保护。

## 独立迁移操作（本轮不对实际数据执行）

本地隔离环境准备安全.env（不要把密钥发到聊天），保持AI_ENABLED=false，然后：

```sh
npm run db:migrate
npm run dev
```

生产标记要求另外显式确认，仅在将来核对目标、备份、停写及恢复验证之后：

```sh
npm run db:migrate -- --confirm-production
```

这不是让你现在执行生产迁移。确认参数不验证备份是否真实有效，也不免除权限要求。迁移只允许单操作者串行执行；并发竞争会失败回滚，不自动重试。不要修改已执行SQL或手动篡改checksum。当前逐版本事务，种子/索引/关联初始化是独立可重复阶段：若中断，重复运行完整命令，直到成功；启动不会自行补救。迁移文件必须随服务器发布包分发。

手机管理员使用：登录现有后台 → 展开“共享 Soul Core” → 载入 → 手动填写 → 保存草稿 → 确认发布。修改后先保存再发布；回滚只切换生效版本。没有服务器测试网址，不能称手机已经可访问新版后台。

## 回滚与遗留风险

本轮没有线上改动，因此无线上数据需要回滚。代码可切回验收基线8e50f81；如以后已共享提交，用新的revert提交，不重写历史。

未来实际迁移后：新增表不应立即删除，保留草稿、历史与审计。旧应用可忽略这些附加表，但新增角色可能缺少关联；重新启用新版时，显式迁移命令会补齐关联并校验。禁止直接恢复旧备份覆盖后续写入。旧应用仍可能恢复自动启动迁移行为，需独立核对实际回滚目标，不能把“切回旧代码”等同无数据库副作用。

迁移台账逐版本原子，不是全部版本的一次总事务；失败时不回退此前已成功的版本。操作前仍需一致性备份、独立恢复验证、单操作者与停写窗口。本轮未提供破坏性down迁移。Core完整历史可能敏感，备份权限/异机加密治理仍待完成。

API每次就绪检查会读取迁移文件和台账，负载较高时需在不失去部署一致性保护的前提下优化。所有本轮通过结果仅针对临时SQLite与Mock，不代表正式上线条件已满足。
