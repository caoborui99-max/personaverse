# 开发管理员额度：第一阶段

来源为 `prepare/deepseek-chat-release` 的 `536b43424a85c8402debc14fd231270385b6d8e1`。独立分支 `prepare/dev-admin-quota-phase1`，不合并main，不连接任何现有服务或数据库，不部署，不执行真实模型请求。

## 生效规则

- 必须显式设置服务端 `AI_QUOTA_MODE=development`，且通过原管理员登录会话验证，才免个人日/月次数限制。仅设置 `NODE_ENV=development`、前端携带role/开发标记、匿名Cookie均不能获得豁免。
- 默认 `AI_QUOTA_MODE=standard`，保留原隔离/访客限额。非法模式拒绝请求。第一阶段没有新增生产用户或会员月额度，也没有后台额度管理，后续设计保留。
- 开发管理员每UTC分钟频率用 `AI_ADMIN_RATE_LIMIT` 调整，默认1、允许1..60；每身份并发锁、请求指纹、重复请求结果复用继续生效。豁免身份不再被旧 `ai_budget` 的全站1次/日计数阻挡；旧表和数据保留。
- API状态/结果使用 `dailyLimit:null`、`monthlyLimit:null`、`remaining:null` 表示开发管理员次数不限；页面明确提示全站费用保护仍有效。
- 不修改人格资料、ID、提示词、管理员验证方式或历史归属键。历史表结构及原40条会话窗口策略保持原样；新增迁移不重写任何历史。

## 费用保护：默认拒绝

仍需 `AI_ENABLED=true` 和原Provider服务端配置。第一阶段所有 Provider 入口还必须满足以下条件，否则不发请求：

| 服务端变量 | 规则 |
|---|---|
| `AI_COST_DAILY_BUDGET_CNY` | 全站UTC自然日预算，正数、最多6位小数，无默认值 |
| `AI_COST_MONTHLY_BUDGET_CNY` | 全站UTC自然月预算，正数、最多6位小数，无默认值 |
| `AI_PRICE_MODEL` | 必须与 `AI_MODEL` 精确一致 |
| `AI_PRICE_BASE_URL` | 必须与实际API基础地址一致，HTTPS，不含用户凭据/查询参数 |
| `AI_PRICE_INPUT_CNY_PER_MILLION` | 该模型输入每百万Token最坏价格，正数，不假设缓存命中折扣 |
| `AI_PRICE_OUTPUT_CNY_PER_MILLION` | 该模型输出每百万Token最坏价格，正数 |
| `AI_PRICE_TOKEN_BOUND` | 经操作者核验该模型后，显式填写 `utf8-byte-upper-bound` |

金额用整数微元（1元=1,000,000微元）及BigInt计算，避免浮点舍入向下；单个配置金额/价格不超过1,000,000元。不会读取或请求供应商实时价格，也不会猜测当前模型收费。预算日/月计量在所有身份和额度模式间共享，不因换人格、会话、管理员或切换模式清零。

估算采用完整消息JSON的UTF-8字节数，加每条消息256及总1024的模板开销预留，并预扣最多256输出Token的费用。操作者必须确认目标模型的分词、模板与计费行为受该上界和所配价格覆盖；未知模型/隐藏收费不能未经核验就填写确认值。**这是按配置价格运行的保守应用预算，不是供应商账单的精确计费或供应商侧硬额度承诺。**

新增两张表：

- `ai_cost_periods`：日/月周期、累计预扣微元、最后请求标识；唯一键为周期类型和起点。
- `ai_cost_reservations`：每请求唯一标识、预扣微元、模型/接口、输入上界、输出上限、价格快照和时间；不存密钥、提示词或对话正文。

在单个数据库事务中，对日/月预算执行带条件的原子更新，末尾用NOT NULL约束确认两项更新均属于当前请求；任意失败整体回滚。SQLite使用现有BEGIN IMMEDIATE，PostgreSQL沿用Neon HTTP事务批处理；不是先读余额再分别扣减。数据库不可用或预扣无法确认时一律禁止Provider。

成功预扣后生成仅在进程内有效、一次性且绑定消息/模型/接口/预算配置/输出上限的许可。真实Provider必须验证许可，直接调用Provider、复用许可、改变消息或配置都会拒绝；出站消息在异步验证前复制，避免校验后被改大。遗留一次性CLI也使用同一账本及许可，仍要求明确确认和私有尝试标记，没有绕过费用保护的入口。

第一阶段为保守预扣：成功、失败、超时和中断都不自动退费，不自动重试；没有引入复杂的实际Token结算或退款系统。可能比实际账单更早触发暂停。请求次数不限不代表费用预算不限。配置缺失时聊天状态显示不可用。仍保留20秒、256输出Token、上下文与响应大小限制、无重定向、错误脱敏及密钥回显拒绝。

## 数据与测试边界

仅新增 `0005_chat_cost_guard.sql`；不修改已有SQL或校验和。新账本不能重构缺少Token和时间的旧财务记录；启用时应按已经发生的费用设置剩余预算，不能把账本初始零误认作供应商历史费用为零。只在独立迁移命令执行DDL，启动、构建和请求不自动建表。

测试使用临时SQLite、合成配置及预加载断网保护。覆盖显式模式、鉴权、分钟频率、去重/并发锁、跨日跨月、价格/预算缺失、预扣回滚、失败保留费用、重开数据库、许可防重放、人格/历史和旧迁移保存。PostgreSQL实库并发、真实分词收费及实际浏览器认证需要后续独立验收，不能从SQLite或Mock结果推定。
