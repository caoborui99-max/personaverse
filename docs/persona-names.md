## 内容边界

server/seed-data.js只改name与提示词里的明确自称。保留“慢慢说完”等普通词语；record-store首句改为“你是「黑胶先生」，「午夜唱片店」的虚构店主”，保留场景及其余故事。现有简介没有需要替换的角色旧称，不擅自重写。种子本身没有background字段，不为填满字段编写新背景。

js/personas.js、preview-dist、docs/preview及静态发布分支保持不变；因此旧版纯静态预览仍显示旧称，数据库前端在实际迁移后才显示正式名称。不要为了此次命名重新构建并覆盖现有静态预览。

## 保守的旧库迁移

独立模块server/persona-names.js及清单server/persona-name-manifest.json保存12个ID、旧新名称、精确自称替换规则和完整资料的旧新规范化SHA256摘要，不存业务用户资料。

只有原发布状态、原排序且整个JSON与原始种子完全一致的角色才进入自动计划；字段顺序不同不影响摘要。任何管理员改动（包括姓名、提示词、背景、权限、时间戳及新增字段）、下架、软删除或数据不匹配均跳过，必须另行人工审核，不能强制覆盖。

新库直接生成正式名称。已有种子标记及INSERT ON CONFLICT保护保留，重复初始化不会覆盖旧角色；这也意味着旧库不会因常规db:migrate或服务启动而自动更名。

计划文件仅含ID、旧新名称、字段列表、摘要和跳过原因，不包含原提示词/背景。应用时重算摘要，拒绝篡改/过时计划；只更新personas.data中name与systemPrompt，并在同一事务更新搜索投影。并发变化导致最终校验失败会整体回滚，不留下部分迁移。

已改为目标资料的计划重复应用为零写入，不重复审计。审计保存在settings的独立persona_names_v1:<操作ID>键，只存ID及时间；不修改schema迁移台账、Core、版本、关联、会话或历史文字。数据库schema没有变化。

## 将来审核后执行（本轮仅临时夹具测试）

先备份并验证可恢复，核对独立目标；不要把连接串、密码或Key发聊天或写命令文本。脚本不自动读取.env，操作者需通过受保护的服务端环境注入配置，保持AI_ENABLED=false。

```sh
node scripts/rename-personas.js --plan /安全目录/persona-name-plan.json
```

预览只读数据库。新计划文件0600且不覆盖同名文件。逐项审核候选及跳过项，确认后再执行：

```sh
node scripts/rename-personas.js --apply /安全目录/persona-name-plan.json
```

生产标记环境必须另加--confirm-production；本轮不执行该操作，也不提供默认目标。所有被跳过的定制角色保留原样，可由管理员以后逐个确认名称修改。Node 24环境下执行；手机没有安全终端时不要尝试把配置粘贴到聊天，只先审阅本方案。

不提供自动破坏性down迁移。当前未对业务库应用，代码回退至882b998即可；以后实际改名后的撤销应单独生成反向审核计划，禁止覆盖旧备份抹去后续聊天/管理修改。显示名称变化不会重写历史对话里的旧称。

## 测试与限制

新增7组测试：12个名称/ID、仅自称差异、种子及摘要一致性；新库和管理员改动保护；只读预览、幂等应用及搜索同步；定制/私有/下架/删除跳过；篡改/过时拒绝；并发全事务回滚；第十三个人格动态创建及核心关联。历史会话与实际Core版本夹具在名称迁移前后逐项保持一致。

旧库自定义程度较高时可能12项全部跳过，这是保护而非迁移失败。严格摘要不能识别“管理员改过后又恰好恢复到完全原始资料”的意图，此时仍需人工审核计划。远端PostgreSQL和实体iPhone未验证，不能将临时SQLite测试视为生产验收。

本轮终验：名称测试7组、独立CLI与整合测试5组、AI12组、DeepSeek10组、MVP5组、大陆4组、Core8组，共51组通过、0失败；npm test报告7个测试文件通过。构建、静态预览白名单/语法/副本一致性、git diff --check通过。浏览器、远端数据库及生产迁移未运行；未调用真实AI、未部署。
